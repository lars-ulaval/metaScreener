# The criteria discrepancy — read this before citing runs A and B as "the
# same input"
# ---------------------------------------------------------------------------
# Run A's criteria table is byte-identical to the already-frozen
# docs/data/study_input/criteria_harmonized_v3.1.0.csv
# (a01ccc73056a987c5459da9c9ec373e08d44803ba9b67c2d48b3bf818e11f73d) and is
# therefore asserted by digest rather than duplicated here.
#
# Runs B and C ran against a DIFFERENT table, committed here as
# runBC_criteria_harmonized.csv. The difference is one row, IC-5, in two
# cells: `operator` is `contains` in run A and `llm` in runs B and C, and
# `what` changes correspondingly from the keyword list
# `training;vocational;workplace` to the criterion sentence.
#
# IC-5 is an **IL** criterion. The EL stage reads only EC-2 and EC-3, and
# those two rows are byte-identical across all three runs — the test asserts
# this field by field rather than leaving it to the reader. EL's 85-record
# input is likewise byte-identical across all three runs. So the A-vs-B
# comparison the document draws is sound.
#
# It is recorded anyway, prominently, because it is a concrete instance of
# exactly what F-155 says about the provenance block: the block records six
# fields, the criteria table is not one of them, and something DID differ
# between runs A and B that no artefact of either run would have told you.
# The document's wording — "every field the provenance block records is
# identical" — is literally true and is now also demonstrably incomplete.
